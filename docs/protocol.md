# Experimental protocol

## Outputs and inputs

For an n-by-m mapping, the minimum and maximum degrees are taken over all nonzero combination coefficients λ. The algebraic degree spectrum is stored as `H[d] = number of nonzero λ whose component has degree d`. The local-search objective is the spectrum sum, `sum(d * H[d])`. All implementations use degree zero for the zero Boolean function. Optional enumeration of the combination coefficients attaining the minimum is checked for correctness but is outside the minimum-degree timing.

The saved fixed-workload corpus contains ten random permutations at every width 3 through 19, six practical instances, and one 8-bit identity control retained for legacy searches. All three metrics cover every random width. Three additional original literature LUTs and their improved versions are in `data/literature/`. Each LUT begins with `n m`, followed by decimal output values in ascending input order. Swap files contain decimal input-index pairs. Explicit files define the workloads; their digests and source details are in the manifests.

The practical instances are PRESENT (4 bits), AES and CLEFIA S0/S1 (8 bits), MISTY1 S9 (9 bits), and MISTY1 FI with subkey 0 (16 bits). FI is a fixed-key nonlinear component. Initial standard-instance properties are tabulated separately; transposition measurements follow the resulting variants. AES was checked against the fixed PEIGEN LUT; the MISTY1 implementation was checked against both RFC 2994 block test vectors.

## Single-thread suite

Every ordinary timing configuration has five repetitions. Random scaling uses ten independently generated inputs at each width. Repetitions restart from the same saved input in separate processes.

**A: algorithm reference comparison.** Both sides use contiguous `int32_t` ANF coefficients, cached monomial weights, reusable buffers and the same compiler options. `reference` transforms coordinate truth tables and independently constructs components as needed. `reference-proposed` implements the proposed elimination or symmetric-difference update. Minimum timing is repeated static evaluation; maximum/spectrum timing commits every saved transposition. A natural swap profile and a high-update profile are both retained. The latter uses pairs affecting at least half the ANF index set. Calibrated batch sizes were frozen before formal timing and are recorded in `protocol/workloads.json` and the task list. A separate instrumented build replays the same workloads for logical-operation counts; its clocks never enter performance results.

**B: optimized implementation comparison.** Widths 3–8 call actual PEIGEN numerical kernels; widths 9–19 use the project's packed traditional implementation (`bitwise`), with 64-bit truth tables, a bitwise Möbius transform and Gray-order component reuse. The proposed implementation uses packed output columns for minimum-degree elimination, 64-component ANF tiles for spectrum updates, sparse symmetric differences, and in-place updates/rollback. Output columns occupy 16-bit lanes up to output width 16 and 32-bit lanes above it. Dynamic baselines retain prepared coordinate truth tables and recompute after each swap. Static timing includes LUT conversion on every call. Each update cycle contains 128 saved swaps; all are committed and state continues between cycles. The 16–19-bit workloads use one minimum evaluation, four cycles (512 maximum updates), or one cycle (128 spectrum updates). `serial-tasks.json` is authoritative for all workload sizes.

The B archive has 5,280 paired timing records: 170 random plus six practical inputs, three metrics, two methods, and five repetitions. Its measured sources are preserved separately as OPT-01 (`src/optimized`, widths 3–16), FINAL-01 (`src/extended`, spectrum 17–19), and MINMAX-19 (`src/minmax`, minimum/maximum 17–19). Every optimized invocation receives the same 50 ms CPU warmup. The older A/reference/count artifacts remain separate and are not substituted for the optimized comparison.

The packed transform and weight-order degree scan reproduce/adapt Bakoev's [2019 method](https://doi.org/10.1007/978-3-030-21363-3_5) and [2020 method](https://doi.org/10.1145/3407982.3408005). This is a project implementation of those techniques. It uses six within-word transform stages followed by word-wise XOR stages, bitwise weight-lexicographic order for n <= 8 and its CB-WLO variant above 8. Gray-order enumeration reuses one component buffer; the maximum-degree baseline only evaluates coordinates. The PEIGEN adapter uses `get_coordinates_ANF` and `degree_from_ANF` for maximum degree, SIMD `degree` for 3–4-bit minimum/spectrum, and `get_components_ANF` with weight-order `degree_from_ANF` for 5–8-bit minimum/spectrum. Checks compare this adapter against the upstream spectrum interface and exclude the zero mask from the histogram.

**Published-LUT postprocessing (main search experiment).** Freyre 2020 S8 and Kuznetsov 2023 S-box2/S-box3 are used exactly as published. Their standard vectorial NL is 104 over all 255 nonzero masks. The objective is the lexicographically ordered pair (minimum degree, spectrum sum). Candidates are index pairs p<q in lexicographic order. The first strict objective improvement with NL exactly 104 is accepted and scanning restarts. Stop at minimum degree 7, or after a full pass finds no admissible improvement. Only the full-spectrum evaluator changes (PEIGEN/proposed). The shared NL routine is called after a strict degree-objective improvement; it accepts only maximum absolute Walsh coefficient 48. Logical candidate copies are implemented by trial swaps and complete rollback. All three cases reach minimum 7 and the saturated spectrum sum 1785. Five repeats per case/method give 30 total-time records, with one untimed full warmup per case/method and the same 50 ms CPU warmup. See `protocol/literature.json` and `scripts/literature.py`.

**Legacy unconstrained searches (additional archive).** The fourteen original 8-bit starts and three separate objectives remain in `group=search`, using the optimized OPT-01 timings. They stop at a full pass without strict improvement, so saturated objectives still inspect 32,640 candidates. They do not impose the literature experiment's NL constraint and are not used for its target-time claims or Figure 4.

## Timing and statistics

`context_ns` measures dimension-dependent setup. `init_ns` measures evaluator-state construction, including its first property evaluation. `kernel_ns` measures subsequent static evaluations, committed updates or the complete local search. `total_ns` is exactly their sum. File reading, correctness checks and result writing are outside these intervals. `process_seconds` also includes process overhead, validation and output.

Execution time per calculation or update is `kernel_ns / steps`; initialization is excluded from Figures 1–3. Figure 4 reports total time to the literature target, including context/evaluator initialization, all candidate degree evaluations, NL checks and rollback. The initial input admissibility check, independent validation and I/O are outside timing. In A, LUT conversion and state construction are also recorded separately.

For single-thread results, take the median of five times for each input, form baseline/proposed ratios within that input, then report the median and interquartile range across ten inputs. Quartiles use linear interpolation over ordered observations. All repetitions and slow configurations are retained. The published scripts recompute all tables and verify saved outputs and work sizes.

For literature cases, report each named input separately: five-run median total times and their ratio. Figure 4 uses three independent vertical scales and shows all repetitions and their ranges. No pooling of the three cases or exclusion of NL cost is used.

## Measurement environment

Measurements used Ubuntu Linux 6.8.0-134-generic, GCC 13.3.0, two AMD EPYC 9754 sockets (256 physical cores / 512 logical CPUs), and approximately 1 TiB of RAM. Build flags were `-std=c++20 -O3 -march=native -fopenmp -Wall -Wextra`. Timed runs bound CPU 0 and NUMA node 0.

The scalar-reference archive contains 824 group-A commands that overlapped for approximately 44 minutes with a separate workload on the other socket and NUMA node. Optimized group-B, search and counting batches did not overlap that workload. All records remain in the archive.
